How it works

1 · Describe
Plain English or YAML
autodemo demo "Sign up, create a project, open the dashboard" — or commit a deterministic .autodemo.yml scenario next to your code.
2 · Run
Real browser, real app
Playwright drives your actual product — local dev, preview deploy, or production — with a visible cursor, click rings, human-paced typing, and auth state support.
3 · Ship
Every artifact, one run
video.mp4 · interactive index.html walkthrough · named assets/*.png marketing captures · reproducible run.json.

Built for humans and AI agents

Bring any LLM
Claude, OpenAI, Gemini, Groq, or fully local via Ollama/vLLM. Auto-detected from your env — and optional: deterministic scenarios need no LLM at all.
CI-native
A 5-line GitHub Action regenerates demos on every merge. A failing demo run is a failing user flow — your demo doubles as a smoke test.
MCP for agents
autodemo mcp lets Cursor, Claude Code, and Codex agents generate and run demos to show their work — videos on every PR.
Versioned with your code
Scenarios live in git, get code-reviewed, and diff like code. No browser extensions, no vendor cloud, no per-seat pricing. Ever.
Authenticated flows
Reusable browser storage state means logged-in demos run against emulators, previews, or production without manual logins.
Marketing-grade output
Dev overlays hidden, loading noise trimmed, named region captures for your homepage and launch posts — straight from the real UI.

Demos as code

# .autodemo.yml — committed next to your app
scenarios:
  signup:
    description: "Signup → first project"
    steps:
      - type: goto
        url: /signup
      - type: act                      # AI step (any LLM)
        instruction: "Sign up with a new email and password"
      - type: click                    # deterministic step
        selector: "[data-testid=new-project]"
      - type: waitFor
        text: "Dashboard"
      - type: screenshot               # named marketing capture
        name: dashboard-hero
        selector: "[data-testid=dashboard]"
# Run locally
autodemo run signup --url http://localhost:3000

# Or in CI (.github/workflows/demos.yml)
- uses: praveen-palanisamy/autodemo@v0
  with:
    url: http://localhost:3000

Frequently asked

What is AutoDemo?

An open-source CLI (MIT) that turns a running web app into demo videos, interactive walkthroughs and marketing captures from a single command. Scenarios are code — YAML or plain English executed by an LLM — so demos are versioned in git and regenerated in CI whenever the product changes.

How is it different from Arcade, Storylane or Navattic?

Those are hosted demo SaaS tools with editors and analytics. AutoDemo is free, runs on your machine or CI, produces video, walkthrough and stills in one run, keeps everything in your repo and is operable by AI agents via MCP. It is for teams who want demos to be build artifacts.

Does it need an LLM?

No. Deterministic YAML scenarios run without any API key. An LLM (OpenAI, Anthropic or local Ollama) is optional for authoring or executing natural-language steps.

Can it run in GitHub Actions?

Yes — uses: praveen-palanisamy/autodemo@v0. Point it at your running app, pick scenarios, and it uploads or commits the generated assets. See the action docs.

Who maintains it?

Praveen Palanisamy. Source, issues and releases: github.com/praveen-palanisamy/autodemo.
